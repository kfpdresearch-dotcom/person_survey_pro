## 0. 한 줄 요약

기존 진단(문항 → 채점 → 생활신호 → 맞춤 서비스 34종)은 **그대로 두고**, 결과 화면 「맞춤 서비스」 탭에서
서비스의 `track` 태그로 **공공(B) 신청 돕기 / 민간(A) 기관·프로그램 찾기**로 갈라 「우리 어르신 돌봄 계획」 한 장으로 모은다.
서버 없이 정적 JSON + 브라우저 저장소(localStorage·IndexedDB)로 돌아간다.

## 3. 데이터 흐름

```
STATE.answers ─ calcDomainScores() ─ extractSignals() ─ recommendServices()   ← 기존, 미변경
        │                                   │                     │ tier1 / tier2 / checkNeeded
        ▼                                   ▼                     ▼
  buildProfile(answers, domains, signals, region)  →  buildItems(recs)  (+안전 고정 · +장기요양 인정신청 선행)
        │                                                     │
        │                                   splitByTrack → public[B,AB] / private[A,AB]
        │                                                     │
        └──────────────→ checkEligibility · rankWithinTrack (트랙 안에서만) · autoGuide
                                                              │
                         S10~S13 (공공 신청)   S20~S26 (민간 찾기)   →  바구니(localStorage) → buildCarePlan → S30/S31
```

### 3-1. 프로파일 (값마다 출처)

| 키 | 진단 문항 | 값 | 출처 |
|---|---|---|---|
| `age` | Q2 출생연도/나이 | 숫자 | diag |
| `sex` | Q1 | M / F | diag |
| `household` | Q6 | single / couple / with_child / other | diag |
| `income` | Q9 | basic(기초생활) / near(차상위) / pension(기초연금) / none | diag, 「잘 모르겠음·답하고 싶지 않음」은 **unknown** |
| `ltcGrade` | Q10 (+바구니) | has / rejected / none / **applying**(인정신청 「신청했어요」) | diag / cart |
| `householdIncome` | Q6+Q9 파생 | ok / no (응급안전안심서비스용) | diag |
| `status` | 영역 점수 | mobility(B) · cognition(D) · isolation(F) = 1 − 점수/100, meal = 식사 신호 | diag |
| `region` | S02 직접 선택 | sido · sigungu · dong + 읍면동 중심좌표 | **user (GPS 미사용)** |

`unknown` 인 값은 자격 대조에서 **탈락이 아니라 「확인 필요」**로 간다.

## 7. 우선순위 (트랙 안에서만)

`score = 0.35·N + 0.20·U + 0.20·E + 0.15·T + 0.10·A` — `RANK_WEIGHTS`(meta.js) 한 곳에서 조정.

| 항목 | 계산 |
|---|---|
| N 필요도 | 연결 신호 sev 최댓값 ÷ 2 |
| U 시급성 | 낙상·고립·식사 신호가 있고 해당 영역이 위험(1) / 주의(0.5) |
| E 자격 | 신청 가능 1 / 확인 필요 0.5 / 해당 없음 0 (A-생활은 장소 이용 연령 기준) |
| T 기존 tier | tier1 = 1, 그 외 0.5 (끼운 장기요양 인정신청은 의존 서비스의 tier) |
| A 접근성 | B: 온라인 신청 있음 1 / 방문만 0.5 · A: 선택 지역에 해당 기관·장소 있음 1 / 없음 0 |

점수보다 먼저: **① 안전 고정**(`SAFETY_PINS`: 학대 위험 → 권리보호, 낙상 2회+ → 주거안전·응급안전·1:1운동, 고립+식사 거름 → 식사배달·공동식사 등) **② 선행 관계**(등급 필요 서비스 바로 위에 장기요양 인정신청) **③ 해당 없음은 맨 아래**. 동점이면 tier → 이름 순. 트랙별 상위 3개 카드 + 「더 보기」.

## 8. 공공서비스 신청 — 3단 폴백

`resolveChannel(apply, env)`: `direct.webviewOk && env.isNative` → **DIRECT** / `link`·`direct` 있음 → **LINK** / 전화 상담만 → CALL / 그 외 → **FORM**. FORM(「방문 신청할래요」)은 온라인이 있어도 항상 보조 버튼으로 열려 있다.

- 현재 웹(GitHub Pages)에서는 DIRECT = 새 탭이라 **LINK로 처리**. 네이티브 래핑(T42) 때 `window.PersonNative = { openInApp(url) }`(iOS SFSafariViewController / Android Custom Tabs)만 주입하면 DIRECT가 켜진다.
- 앱은 대신 제출하지 않는다. 신청 직전까지(정보·준비물·서식·작성 도우미)만 준비.
- 진짜 온라인 신청이 있는 곳만 LINK로 둠: 에너지바우처(복지로), 노인일자리(노인일자리 여기), 장기요양 인정신청(노인장기요양보험 누리집). 나머지는 참고 링크(`ref`)로만 표시.
- 제휴 접수(`partnerApi`)는 경로 하나를 더하는 식으로 붙일 자리만 비워 둠 — 법률 검토 선행.

## 9. 진행 상태 (모두 사용자가 버튼으로 바꾸는 자기 표시)

`saved(담음)` → `preparing(준비 중: 체크 첫 표시·서식 받기·서류 첫 업로드·신청 페이지 열기)` → `submitted(신청함)` / `contacted(연락함)` → `done(선정됐어요 | 안 됐어요)`
- 장기요양 인정신청이 `submitted` → 민간 탭·기관 목록·돌봄 계획 상단에 「등급이 나오면 다닐 곳을 미리 비교해 보세요」 카드, 프로파일 `ltcGrade = applying`.
- `done(안 됐어요)` → 공공 탭에 같은 영역의 비슷한 서비스 제안.

- 결과 첫 진입: 지역이 없으면 S02부터(카드의 버튼으로 들어왔으면 지역 선택 후 그 서비스로 이어짐).
- S03 카드 미리보기: A-돌봄 → 가까운 기관 2곳(읍면동 미선택 시 평가등급 순), A-생활 → 접수 중 프로그램 2개(없으면 장소 2곳), B → 신청처와 신청 방법 배지.
- 새 소식(최대 3건): 새로 접수 시작한 강좌, 접수 마감 3일 전, 정원 여유가 생긴 기관, 신청기간이 열린 제도 — **바구니 + 트랙별 상위 3개 서비스**만 대상, 스냅샷 `version`·마지막 확인일과 비교.
- 재진단 권유: 마지막 진단 90일 후 배너. 재진단 뒤 「새로 추천 / 순위가 올랐어요」 배지.
- 관리자 사례로 결과를 열면 S03·S30 하단에 「새 소식 미리보기」「90일 지난 상태 보기」 확인용 버튼.
